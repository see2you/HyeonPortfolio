채굴 빠른 일괄 배치

소유자: 김현

    • 목적
      • 개인 채굴 컨텐츠에서 부하 배치 시의 터치를 줄일 수 있도록 UX를 개선
    • 목표
      • 개인 채굴 컨텐츠의 [자동 배치] 기능의 연산 처리 규칙을 편의성이 높아질 수 있는 형태로 보완
    • 개선안
      • 개인 채굴 컨텐츠의 [자동 배치] 기능의 규칙을 변경하고, 기능명을 [최적 배치]로 변경

[현재]

    • 스태미너 조건을 만족하는 부하만 배치
    • 전투력이 높은 순으로 부하를 배치
    • 배치 슬롯이 전부 채워질때까지 연산 처리 반복
    • (1.0 기준 최대 배치가능 슬롯 = 3개)
      • 예시 : A(90), B(80), C(70), D(60) 부하를 보유하고 있는 상태이고, 총 전투력 100을 요구하는 스팟에서 [자동 배치] 클릭 시, 부하 A, B, C가 자동 배치됨.
    • 단, 배치할 수 있는 부하가 슬롯보다 적을 경우에는 가능한 만큼만 배치

[변경 후]

    • 스태미너 조건을 만족하는 부하만 배치
    • 1순위로 보너스를 제공하고, 단일 배치로 요구 조건을 만족하면서 전투력이 가장 낮은 부하를 배치
    • 2순위로 보너스를 제공하고, 다중 배치로 요구 조건을 만족할때까지 전투력이 낮은 순으로 부하를 배치
    • 3순위로 보너스를 미제공하고, 단일 배치로 요구 조건을 만족하면서 전투력이 가장 낮은 부하를 배치
    • 3순위로 보너스를 미제공하고, 다중 배치로 요구 조건을 만족할때까지 전투력이 낮은 순으로 부하를 배치
      • 예시 : 보너스를 제공하는 A(100), B(70) / 보너스를 미제공하는 C(100), D(80), E(60) 부하를 보유하고 있는 상태이고, 총 전투력 100을 요구하는 첫번째 스팟에서 [최적 배치] 클릭 시, 부하 A가 최적 배치됨 (100 ≥ 100).
  • 그 다음 총 전투력 100을 요구하는 두번째 스팟에서 [최적 배치] 클릭 시, 부하 B, E가 최적 배치됨 (70+60 ≥ 100).
  • 그 다음 총 전투력 100을 요구하는 세번째 스팟에서 [최적 배치] 클릭 시, 부하 C가 최적 배치됨 (100 ≥ 100).
  • 그 다음 총 전투력 100을 요구하는 네번째 스팟에서 [최적 배치] 클릭 시, 요구 전투력을 만족하는 배치가 불가능하므로 토스트 메시지를 노출 (해당 문구는 예외처리 2번 참조)

[알고리즘 제안 (승민)]

    • 보유한 부하를 4개의 그룹으로 분류한다
      • 1순위 : 보너스 제공 + 스태미너 있음
      • 2순위 : 보너스 미제공 + 스태미너 있음
      • 3순위 : 보너스 제공 + 스태미너 없음
      • 4순위 : 보너스 미제공 + 스태미너 없음
    • 각 그룹을 전투력 높음 -> 낮음 순위로 정렬한다
    • 약한 부하부터 선택
      • 높은 우선순위 그룹 -> 낮은 우선순위 그룹으로 순회
        • 한 그룹 내에서는 약한 부하 -> 강한 부하로 순회
          • 선택된 부하가 3명 미만이면, 부하를 선택 목록에 추가한다.
          • 선택된 부하가 3명이면, 그 중 가장 약한 것보다 현재 부하가 강한지 본다
            • 현재 부하가 더 강하다면 가장 약한 부하를 빼고 현재 부하를 추가한다.
          • 위 처리를 한 뒤에, 선택된 부하의 전투력 합이 요구 전투력을 충족시키면 종료
          • 아니라면 다음 부하로
      • 위 과정이 끝나면 선택한 부하들이 요구 전투력을 충족했는지 확인
        • 충족했다면, 선택한 부하를 강한 부하 -> 약한 부하로 순회하면서, 이 부하를 빼도 요구 전투력을 충족하는지 보고 충족된다면 뺀다.
          • 100을 요구하는 개인 채굴에서 10, 30, 90 이렇게 선택했을 때 30을 빼버리기 위한 과정

[구현 가능한지 검토가 필요한 항목]

    • [최적 배치] 클릭 시 요구 전투력 조건을 만족하지 못해 배치가 불가능한 상태지만, 특정 부하의 스태미너만 다시 회복하면 개인 채굴 배치가 가능할 경우
      • 빠른 회복 재확인 팝업을 노출
      • 팝업에서는 회복 대상 부하의 포트레이트와 회복량을 노출 (최대 3명까지 노출되는 형태를 고려하여 제작)
      • [회복] 버튼 클릭 시, 개인 채굴 입장에 필요한만큼의 스태미너만 회복 후 자동으로 배치되어 채굴 시작
      • UI까지 신규 제작까지는 어려울 경우 전체 회복 팝업을 동일하게 사용 (상단 제목 문구만 ‘빠른 회복’으로 바꿈)

[예외 처리]

  • 1. 보너스를 제공하는 부하들로만 최대 슬롯까지 배치했지만, 요구 전투력 조건을 만족 못할 경우
    • 가장 높은 부하를 배치에서 제외하고, 전투력 요구 조건을 만족시키면서 전투력이 가장 낮은 보너스를 미제공하는 부하를 배치
  • 2. 동일한 자원 채굴장의 다른 스팟에서 채굴 중인 부하를 제외한 가장 강한 부하를 최대 슬롯까지 배치해도 요구 전투력 조건을 만족 못할 경우
    • 부하가 자동으로 배치되지 않고 토스트 메시지를 노출
    • optimal_placement_impossible_not_enough_crew_power : 채굴장의 요구 전투력을 만족하는 부하 배치가 불가능합니다.

[제약 요소]

    • 최적 배치 후 초과되는 전투력이 무의미하게 낭비되는 비효율 문제 발생
      • 해당 문제를 최대한 보완하기 위해 전투력이 낮은 순으로 최적 배치를 하는 규칙으로 설계
      • 전투력이 낮은 순으로 배치를 하더라도 문제점이 완벽하게 보완되지는 않지만, 요구 전투력에 가능한 한 근사치로 최적 배치될 수 있도록 유도
      • 보너스 제공 유/무를 고려하는 동시에 요구 전투력에도 근사하도록 최적 배치되는 사양으로 설계하는 것을 고려해봤으나, 클라이언트의 연산 처리로 인한 부하 요소 및 개발/테스트 공수가 커지게 되는 문제점이 발생

[추가 폴리싱]

    • 개인 채굴 UI의 모든 [자동 배치] 버튼을 [최적 배치]로 문구 변경
      • 개인 채굴, 병력 배치 UI

[일괄 최적 배치 기능 추가]

    • 자원 채굴장 단위로 부하를 일괄 최적 배치할 수 있는 기능을 추가
    • 매일 설정해야 하는 채굴 컨텐츠의 수동 조작 뎁스를 더욱 최소화하여 지금보다 개선된 UX를 제공하고 기획 사양이 시스템으로 인해 제한받지 않도록 보완

[일괄 최적 배치 기능 시스템 규칙]

    • 자원 채굴장 메인 UI에서 원터치로 부하를 일괄 최적 배치할 수 있는 [일괄 최적 배치] 버튼을 추가
    • 버튼 클릭 시, [일괄 최적 배치] 재확인 팝업 노출. 이 때 자원 채굴장 메인 UI는 그대로 유지
      • 스트링 키 : optimal placement_reconfirm
  • ‘일괄 최적 배치를 하시겠습니까?
  • 예를 누르시면 최적 배치 후 채굴이 자동으로 시작됩니다.’
    • 예 클릭 시, 클라이언트에서 배치 가능한 채굴 스팟들에 순차적으로 최적 배치 연산 처리를 진행
  • (채굴 스팟은 UI상으로 위에서 시작하여 아래로 배치)
    • 아니요 클릭 시 팝업이 닫힘 처리되고 동작 종료
    • 위 과정이 끝나면 남은 배치 슬롯과 배치되지 않은 보너스 부하가 있는지 확인
  • 이 과정은 일괄 최적 배치 후, 남는 자투리 보너스 제공 부하가 없도록 하기 위함이 목적 (밸런스팀 희망)
    • 먼저 남은 배치 슬롯 정보를 조회
    • 두번째로 현재 채굴에 배치되지 않은 부하들을 약한 부하에서 강한 부하 순으로 조회하면서, 보너스 여부가 있는 체크
    • 마지막으로 보너스가 존재하는 배치되지 않은 상태의 부하가 존재할 경우, 스태미너 조건을 체크
    • 스태미너가 충분할 경우 첫번째 스팟의 빈 슬롯부터 조회된 순으로 부하 배치
    • 스태미너가 충분하지 않을 경우, 후술될 스태미너 빠른 회복 대상에 포함 처리
    • 만약 빈 슬롯보다 조건을 만족하는 부하가 더 많을 경우, 해당 부하들은 배치 대상에서 제외됨
      • 어떤 수를 쓰더라도 배치가 불가능함
    • 연산 완료 후, 모든 부하가 스태미너 조건을 만족할 경우 자동 배치 후 채굴 시작됨
      • 만약 최적 배치가 가능하지만 스태미너가 부족하여 불가능할 경우, [빠른 회복] 재확인 팝업을 노출
  • 이 때 [일괄 최적 배치] 팝업은 자동으로 닫힘 처리됨.
    • 스트링 키 : not_enough_stamina
    • ‘스태미너가 부족한 부하들이 있습니다.
    • 회복 후 일괄 최적 배치가 가능합니다.’
    • [빠른 회복] 재확인 팝업에서 [회복 후 배치] 버튼 클릭 시, 현재 보유중인 식량 조건을 체크
      • 취소 버튼 클릭 시 팝업이 닫힘 처리되고 동작 종료
    • 식량 조건 만족 시, 대상 부하들의 스태미너가 모두 최대치까지 회복되고 자동으로 최적 배치 후 채굴을 시작
    • 식량 조건 불만족 시, 식량을 다이아로 구매 확인 팝업을 노출 (기존 사양과 동일)

[일괄 최적 배치 기능 예외처리]

    • 스태미너가 회복되더라도 채굴 조건(요구 전투력)을 만족하지 못하는 케이스의 부하들은 빠른 회복 대상에서 제외
    • 빠른 회복 대상이 될 경우, 스태미너는 기존의 전체 회복 기능과 동일하게 최대치까지 회복됨
    • 자원 채굴장에서 1개 이상의 스팟에 배치가 불가능한 상황일 경우 하기와 같이 처리
      • 모든 스팟이 이미 ‘채굴 중’ 또는 ‘채굴 완료’ 상태일 때
        • 버튼이 GREY 처리됨
        • 토스트 메시지 optimal_placement_impossible_not_enough_mine 출력
        • ‘배치 가능한 채굴장이 없습니다.’
      • 1개 이상의 개방된 스팟이 있지만, 스태미너 조건을 만족하더라도 요구 전투력을 만족하는 최적 배치가 불가능할 때
        • 버튼이 GREY 처리되지 않음
        • 토스트 메시지 optimal_placement_impossible_not_enough_crew_power 출력
        • ‘채굴장의 요구 전투력을 만족하는 부하 배치가 불가능합니다.’

[빠른 회복 UI 노출 규칙]

    • 대상 부하 이미지는 포트레이트, 등급 백그라운드, BONUS 유무만 노출
    • n행 X 4열 의 구조를 가지며, 동시 최대 노출 가능한 수는 8개 (2행 X 4열)
      • 대상 수가 초과할 경우, 스크롤이 활성화되며 이미지는 좌측에서부터 소팅 처리
