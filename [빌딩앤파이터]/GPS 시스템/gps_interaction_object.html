1️⃣개요

히스토리

유물상자(물음표)가 생성되어진 곳으로 유저가 이동했었다.

스캐너를 돌리고 상자가 생성된 위치로 이동을 했다.

보상위치가 정해져있어서 수동적으로 걸어다녀야만 했다.

진행방향

유저가 이동하는 경로에 보상(주머니)가 보여질 것이다.

능동적으로 걸어다닐 때, 보상이 보인다.

물음표 생성은 그대로 유지한다. (유저의 이동 목적이 되어야하니까)

다만 유저의 위치에서 좀 더 멀리서 생성되어도 된다.

주머니란?

                스캐너 또는 유저가 해당지역에 머물렀을 때 생성되는 보상이 아니라

                맵에 퍼져있는 보상을 유저가 찾아다니면서 먹을 수 있는 개념.

                B5에서는 물음표(암상인 또는 유물상자)가 유저에게 이동할 방향성을 제시할 것이며,

                이동 중에 발견되는 주머니를 추가적으로 얻는 방식으로 진행.

                유저 주변에 있을 때만 보여지고 거리가 멀 경우 보이지 않는다.

                주머니를 오픈

메가폰을 지불해서 오픈한다.

                무료오픈을 하기 위해서는 주머니 위치까지 이동해야한다. (보정 80m - 유물상자와 동일)

다만 나오는 자원의 차이는 크다. (메쉬구분은 없지만 자체적 레어리티는 있어야함. 생성확률 조절 스크립트 필요)

  3. 거리 (보정값(80)을 제외하고 0m일 때, 햅틱과 꿈틀 애니매이션

주머니 생성

                예시 이미지)    헥스 1개당 주머니 1개가 생성되는 방법 (헥스로 풀어본다.)                

배치 방법

헥스

월드맵은 헥스로 이루어져 있으며, 헥스의 묶음으로 월드맵을 표시할 수 있다.

헥스를 구분할 때 기본 19개의 헥스가 한 묶음으로 한다.

                

유저의 시야 범위

반지름 대략 200m (80m + 120m)

        주머니가 배치될 헥스

의도

중심헥스의 GPS를 이용하여 19헥스에서 주머니가 생성될 위치를 책정한다.

매일 같은 위치에 생성되면 유저에게 쉽게 패턴이 파악되기 때문에 일정한 규칙을 가지고 랜덤하게 뿌려진다는 느낌을 유저에게 주도록한다.

규칙

  1. 하루 획득제한량이 있다.
  2. 한번 생성된 주머니는 다음날(오전6시)에 초기화 된다.
  3. 유저마다 주머니가 생성되는 헥스의 위치는 동기화  (다를 수 있다.)
  4. 19개의 헥스에 최소 N개의 주머니는 확정적으로 생성된다. 100% (어디에 생성될지는 랜덤)
    1. 단, 유저가 최초 접속한 헥스의 인근 헥스에 주머니를 1개 생성한다.
  5. 헥스 19개에 최대 생성가능 주머니 수는 최대 19개 (생성위치 랜덤)
    1. 1개씩 증가하는 확률은 스크립트로 제어 (3개, 4개, 5개...19개)
    2. ex) 가중치로 데이터 작성. (2개까지는 확정적으로 된다는 예제)
      1. 1개         100%
      2. 2개         100%
      3. 3개         50%
      4. 4개         10%
      5. 5개         1%
  6. 주머니가 생성되는 위치는 건물과 위치가 겹치면 안되기 때문에
    1. 각 헥스의 하단부분에서 생성되도록 한다

4️⃣유저 시야 처리

시야 밖의 주머니는 어떻게 알 수 있는가?        

‘시야범위보다 + 헥스 1칸’  거리에 있는 주머니는 알파 50%의 오브젝트로 보여진다.
시야범위에 가까울수록 짙어지도록 하는 것이 의도.
반투명한 주머니가 보여지는 거리는 ‘시야거리’ + 50m (스크립트)
예시)
시야거리경계에서 100m 멀 경우 = 투명도 80%
시야거리경계에서 10m 멀 경우 = 투명도8%		시야범위 내에 들어왔을 때 투명도는 없다.

빠른 속도로 이동할 때 주머니를 계속 보여줄 것 인가?    

No

시속 12Km미만인 경우만 주머니를 볼 수 있다.

        체크방법:

시속 12km일 경우 초속 3.333m

캐릭터 이동체크할 때 이동거리가 초당 3.333m이상일 경우 (체크간격 10초 -- 변동될 수 있습니다.)

캐릭터 시야 붉은 원 + 토스트 메시지 (이동속도가 너무 빠릅니다.)

체크간격마다 토스트 메시지 노출

주머니 생성 / 획득 관련 클라 - 서버 구현 방법 정리

  • 한 헥스에는 주머니가 하나만 스폰되고, 그 주머니를 해당 헥스에는 주머니가 스폰 안되므로, 서버/클라 통신때 주머니가 스폰된 헥스 인덱스를 주머니의 식별자로 사용한다.
    • ex : col=19381, row=2711의 주머니를 까도록 서버로 요청함
  • 로그인때 서버에게 오늘 깐 주머니들의 목록을 받는다
  • 클라이언트
    • 클라이언트에서는 유저가 현재 위치한 헥스가 바뀔 때마다, 매니저에게 내 주변에 위치한 박스들의 헥스/좌표 목록을 요청한다. (시드를 통해 계산하므로 서버 요청 필요x)
      • 헥스가 바뀔때 요청하는 것은 너무 자주 요청해서 생기는 부하를 방지하기 위함.
      • UIU_GpsDataManager::GetNearGpsPocketSpawnInfos함수로 구현 완료
      • 이때 실제로 보여야 되는 범위보다 넉넉한 범위의 박스를 리턴함
      • 목록을 받아서 오늘 이미 깐 헥스는 제외시킨 뒤, 현재 스폰된 주머니 오브젝트를 갱신한다. (새 목록에 없는 것 파괴 / 오브젝트가 없는 것 스폰)
    • 주머니와 나와의 거리에 따라 visibility / 투명도 / 애니메이션을 갱신한다 (이 처리는 위치한 헥스가 바뀌지 않아도 내 위치 좌표 변경때마다 해야 함)
    • 주머니 깔 때 서버로 요청한다.
      • 까는 연출에 레어리티 결정이 필요하므로, 일단 요청해서 응답을 받은 뒤에 주머니가 까지는 연출을 한다.
  • 서버
    • 특정 헥스의 주머니를 까는 패킷이 오면 csc함수를 이용해 다음과 같은 검증을 한다
      • 이 유저가 오늘 이미 깐게 아닌지
      • 해당 헥스에 실제로 주머니가 스폰되었는지 (CheckGpsPocketValiditySample 코드 참조)
      • 유저와 실제 주머니 스폰 좌표가 너무 멀지 않은지 (CheckGpsPocketValiditySample 코드 참조)
    • 서버에서 레어리티를 결정해서 클라이언트로 응답으로 내려준다.
  • 남은 과제
    • 일일 초기화때 바뀌는 랜덤시드를 어떻게 계산할 것인가?
      • 그냥 날짜+시간으로 잘 계산해야 되나?
      • 로그인때 서버에서 시드를 받고 일일초기화 태스크에서 일일초기화때 다시 그날의 시드를 받는 처리를 해야 되나?
